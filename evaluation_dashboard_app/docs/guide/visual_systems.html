Viewers & 3D

See the frame behind the metric.

Four viewing systems, one color language. Bounding Box Viewer draws BEV frames from parquet. T4 3D Viewer pushes eval boxes into the T4 server’s Three.js scene. Local 3D BBox Viewer serves a standalone explorer/viewer pair straight from parquet — no T4 server needed. T4 Dataset Server is the integration console for the service the first two depend on.

Bounding Box Viewer (BEV)

pages/4_Bounding_Box_Viewer.py · needs parquet + Overview selection

Frame-by-frame inspection of detection results. Pick a scene (suite + scenario + dataset) and a topic; the page draws every GT and EST box for one frame as a Bird’s-Eye-View plot, color-coded by status, with the ego vehicle at the origin and a notch showing each box’s heading. Optional camera images for the same frame come from the T4 visualizer server.

BEV viewer · frame KPIs

Scene filters in the sidebar, the frame slider, per-frame KPIs (TP / FN / FP / TP-EST / TPR), and the status legend above the BEV plot.

BEV viewer · scene analytics

Below the plot: detection stability per frame, the high-FN-rate object ranking, and the per-UUID trajectory inspector.

What to know

  • Filters — suite, scenario, dataset, one topic, labels, visibility; “Show invalid (zero-size) objects” and “Show velocity vectors” toggles (velocity arrows = 2 s of travel).
  • Camera preview — needs a reachable t4-server that actually hosts the dataset (an availability check runs first). Two modes: an embedded /render/html iframe, or POST /render PNGs with crop/annotation options.
  • Compare mode — side-by-side BEV columns with a shared axis range, or a single overlay where line style encodes the run (solid / dash / dot / dashdot) and color still encodes status. A quick-view radio collapses to one run.
  • Deep links — Detection Stats tables link straight here with suite/scenario/dataset/frame pre-set.
Blank camera panel?

“T4 preview skipped” messages tell you which of the three conditions failed: the scene has no dataset ID in parquet, the server could not be reached (check the base URL in the sidebar, default from T4_VISUALIZER_BASE_URL), or the dataset is not on the server host.

T4 3D Viewer

pages/5_T4_3D_Viewer.py · needs parquet + t4-server

Embeds the T4 server’s Three.js scene (/viewer/three) and pushes the run’s evaluation boxes into it as real 3D overlays — GT, prediction, and UUID-matched pairs. The whole scene’s per-frame boxes are transferred once as a compact binary payload, so scrubbing time inside the viewer never reloads the page.

T4 3D viewer

What to know

  • Shared filters — the same suite/scenario/dataset/topic/label/visibility state as the BEV page (they hand off to each other).
  • Compare in 3D — all selected runs ship into one scene; layouts side_by_side, curtain, or overlay, round-tripped through the viewer_compare URL parameter.
  • Everything is linkable — viewer_suite, viewer_scenario, viewer_t4dataset, viewer_topic, viewer_frame, viewer_compare plus the run parameters make a URL that restores the exact 3D view.
  • Legacy-scene reconciliation — when a run’s parquet doesn’t contain the exact selected scene (renamed suites, different dataset names between releases), the page falls back through exact-scene → suffix-matched scene chosen by nearest GT geometry → topic-only, and reports the match type in the transport debug expander.
  • Debug expanders — “Access / request header debug” (Cloudflare identity) at the top; “T4 overlay transport debug” below the viewer with payload statistics and alignment info.

Local 3D BBox Viewer & Dataset Explorer

pages/15_Local_3D_BBox_Viewer.py + backend/local_bbox_api.py · parquet only, no T4 server

A self-hosted, parquet-backed viewing system that runs entirely from local files. The Streamlit page just launches it: the real UI is two standalone browser apps served by a small local API — opened outside the Streamlit iframe so canvas, fullscreen and keyboard input work normally.

Local BBox launcher
FIND PROBLEMS

Dataset BBox Summary (explorer)

Scans a whole dataset for problem scenarios: issue lenses (FP, FN, rates, TP error, intent risk — plus compare lenses like “More FP/FN in B”), label and ego-range chips, shortcut filters (nearby pedestrian FP, animal/debris, false stop), a hotspot map with a floating scene preview, and a stats drawer with CSV export.

INSPECT ONE SCENE

Local BBox Viewer

Plays back one scene in BEV or perspective: camera presets (Top / 3D / Follow), layer chips with live counts (GT·TP, GT·FN, EST·TP, EST·FP), color/label/lens modes, velocity and range rings, per-frame KPIs, distance-zone strips, issue-frame navigation, and an inspect panel per object (position, size, errors, confidence, UUID).

Compare and shortcuts

  • Tick “Compare with Run B” and pick a second parquet — side-by-side or a draggable curtain wipe, with lenses like New FP in B, Resolved FN in B, B worse TP error, and A / B / Δ summary cards.
  • Keyboard — Space play/pause, ←/→ step, F fullscreen, H hide sidebar, C compare, V layout, L cycle lens.
  • The same explorer/viewer pair is what the local desktop client serves offline against pulled runs.
How it’s served

Locally, a background API starts on 127.0.0.1:8765 (override LOCAL_BBOX_API_PORT). In the Docker deployment nginx proxies it at /bbox-api/, with the apps at /bbox-explorer/ and /bbox-viewer/. If the buttons lead nowhere, the API isn’t running or the nginx routes are missing.

T4 Dataset Server console

pages/11_T4_Dataset_Server.py · integration & debugging

A console for the T4 visualizer HTTP service that the camera and 3D previews depend on. It exercises the same client the viewer pages use — GET /health, GET /datasets, GET /datasets/{id}/scenarios, POST /render — renders camera PNGs in-page, and generates copy-paste embed artifacts: context JSON, share query strings, a GET render URL, and a ready-to-run curl command. Self-contained; no Overview run needed.

T4 Dataset Server console
Use it when a preview won’t load

This page is the natural first stop for “why doesn’t my camera preview render?” — press GET /health, list datasets/scenarios, and try a manual render with the exact IDs the viewer page was using. Server-side calls use the sidebar base URL; browser links use T4_VISUALIZER_BROWSER_BASE_URL.
