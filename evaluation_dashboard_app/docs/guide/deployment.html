Deployment & Operations

Run it on a laptop, or run it for the whole team.

Three modes: plain local Streamlit for development, the Docker production stack (Nginx → Streamlit → Redis/RQ workers → Postgres) for shared multi-user operation, and the local desktop client for offline viewing of pulled runs.

nginx :80 streamlit :8501 bbox api :8765 redis · postgres · workers
Mode 1 — Local

Development on one machine.

cd evaluation_dashboard_app
pip install -r requirements.txt      # includes private deps via SSH
source path_to_pilot/install/setup.sh   # only needed for Summary/Score generation
streamlit run Overview.py

Without USE_TASK_QUEUE, heavy work (downloads, eval, parquet) runs inline in the Streamlit process with progress HUDs. Config lives in configs/autoware_evaluator_dl_config.json (auto-created).

Mode 2 — Production

The Docker Compose stack.

Streamlit becomes UI-only: it enqueues jobs to Redis and reads task status from Postgres; workers do the heavy lifting. One Streamlit replica by default (a second sits behind the ha compose profile). Shared team tool by design — no per-user login; put access control at the network layer (VPN / Cloudflare Access / auth proxy).

./06_STATUS.sh  ./07_LOGS.sh  ./05_STOP.sh
./09_RESTART_WORKER.sh ./10_RESTART_STREAMLIT.sh
./11_ENABLE_EXPORT_API.sh --apply   # client export token setup
./12_VERIFY_EXPORT_API.sh <url> <token>
restart ≠ recreate

docker compose restart reuses the existing container config and never re-reads deploy/.env. Adding or changing an environment variable requires docker compose up -d (recreate). Also: deploy/.env is the only env file compose loads — a .env.local is loaded by nothing.

Bind mounts worth knowing

  • ../data → /app/data — the run folders; ${HOME}/.webauto → /root/.webauto — evaluator credentials (must exist before start).
  • The app source is bind-mounted, so code edits apply without rebuilding — Streamlit auto-reloads; the worker needs restart worker. Rebuild only for dependency/Dockerfile changes.
  • /var/run/docker.sock — powers Deployment Debug and Local Evaluator Debug builds.

VariablePurpose
EVAL_DASHBOARD_DATA_ROOTData root (/app/data in Docker); every user path is confined under it

Operator Console

Deployment Debug (Docker-only page).

Visible only inside a container. Tabs: Environment (redacted env vars), Dependencies (Postgres / Redis / RQ health), Tasks (rows by status), Database (table sizes plus a searchable raw tasks inspector with per-row parameters/result/log drill-down), and Docker — live container table, an auto-generated Mermaid diagram of the running stack, container log tails, a T4 server probe, and (when EVAL_DEPLOYMENT_DEBUG_EXEC=1) one-shot commands inside a container.

Gate it

Anyone who can open this page with socket access can read container logs — and run commands if exec is enabled. Keep it behind VPN/SSO, scope it with EVAL_DEPLOYMENT_DEBUG_COMPOSE_PROJECT, and leave exec off unless actively debugging.

Mode 3 — Offline

The local desktop client (evaldash-local).

Pulls already-generated results from a running dashboard into ~/.evaldash/ and serves the same bbox explorer/viewer against them — offline, no VPN, no Streamlit, no database. It reuses the dashboard’s own API and renderers; the client adds transport, a workspace, and a window (pywebview, falling back to the system browser).

HOME PAGE CARDS

Connect → list → pull → open

Server card (URL + optional token + Cloudflare Access service token), runs-on-server table with per-tier size, downloads with progress and cancel, downloaded-runs table, and a 3D point clouds & cameras card that fetches T4 scenes from a t4-server for local 3D playback (size estimate first — scenes are hundreds of MB).

DOWNLOAD TIERS

criteria is the default

minimal (parquet + metadata) · criteria (+ scenario YAML + pre-baked verdicts, ~18× smaller than the raw run) · full (+ TN preview overlay) · raw (+ scene_result.pkl, ~the whole run). Pulls are resumable, sha256-verified, and incremental. 

python3 -m client login --server https://dashboard.example   # or bake it into the build
python3 -m client runs                    # list what the server has
python3 -m client pull <run> --tier criteria
python3 -m client open --page explorer   # home | workflow | explorer | viewer
python3 -m client doctor                  # connectivity + environment checks
Server side of the client

Export routes ride the existing /bbox-api/ nginx mapping. Access model: direct LAN hits allowed, Cloudflare-authenticated allowed and logged, valid EVAL_EXPORT_TOKEN always allowed, wrong token → 401. “Export API is disabled” (503) means the token isn’t set inside the container — recreate, don’t restart. Pre-bake DevOps verdicts with python3 -m backend.prebake_cli --all --role devops or the criteria panels report unavailable.
