Specsheet & Trends

The release document, and the history behind it.

A release trend group bundles the three role summaries of one release (full / usecase / devops). The spec-sheet is the PDF generated from a release run — optionally with trend context plotted from every previous release. Trend Insights is the page that reads the whole history.

The Release Pipeline

From two catalogs to a versioned history entry.

01Release workflowWorkflow page → Start new workflow → “Release data workflow”. Schedules the fixed Performance + DevOps (+ optional Planning Test) catalogs, or reuses existing job IDs.
02MetadataRelease metadata YAML (tags, release_group, pilot_auto_version, data_count, description, date) is edited inline with live validation, or hydrated from an existing folder.
03SpecsheetThe workflow (or Overview’s export section) generates the spec-sheet PDF, with trend plots when trend mode is on.
04HistoryThe release joins the trend inventory; Trend Insights and future trend-mode specsheets pick it up automatically.
Spec-sheet Generation

What goes into the PDF.

Generated from Overview’s Export Specsheet Report section (or automatically by the release workflow). Inputs: Project ID, Version and Topic name (auto-filled from release metadata), the run’s parquet/CSV artifacts, and — in trend mode — validated trend metadata.

ALWAYS

Abstract + detail blocks

Per-label metric blocks from perception_catalog_analyzer: mAP, precision, recall, FNR, max consecutive FN duration, x/y/yaw/speed error — plus minADE/minFDE @1/3/5 s when future data exists. Default labels: car, truck, bus, bicycle, pedestrian, motorcycle.

TREND MODE

Trend context

mAP trend, prediction trend, current pass-rate plot and pass-rate trend plots rendered into specsheet/trend_assets/, built from every discovered release’s metadata (merged, de-duplicated, sorted by date). Requires valid trend metadata for the current release.

  • Freshness — if the PDF is newer than all source artifacts, generation is skipped and the existing PDF is offered (“Using existing up-to-date spec-sheet PDF”); a Regenerate button forces it.
  • Editing saved metadata — the YAML editor validates live; changing saved metadata requires ticking “Confirm saved metadata changes”, and the edit is written back to the release’s role directories.
  • Manual history — “Choose trend history manually” lets you pick exactly which past releases appear in the trend plots; the current release is always included.
  • Multiple runs — in compare mode you can queue several runs; output is one specsheet.pdf or a specsheet_reports.zip. Trend mode supports exactly one run at a time.
  • Publishing — generated PDFs are linked into static/release_specs/<release>/<topic>.pdf so the browser can open them straight from the Trend Insights history table.
Metadata format is strict

date must be YYYY.M.D (e.g. 2026.5.22) and data_count digits with optional commas/+. Trend-group assembly also insists each summary file actually classifies as its declared role — a usecase summary can’t be registered as devops.

The History Page

Trend Insights: every release on one page.

Reads all release trend groups plus the specsheet inventory and renders the release history, cross-release performance tables and trend charts, defect breakdowns, and per-release deep dives. A History category control (All / Release / Periodic Evaluation) filters the whole page.

Trend Insights · release history

The Release History table: type pills (Release / Periodic Evaluation), per-role “Open” links that deep-link Overview, spec-sheet PDF links, and evaluator report links. Clicking a type pill flips a release between Release and Periodic Evaluation by updating its metadata.

Trend Insights · trend charts

Sections, top to bottom

  • Release History — sortable inventory: version, type, date, description, data count, per-role Overview links, specsheet PDFs (Prediction / Detection columns), evaluator job reports, folder.
  • Release Performance — Perception Performance vs ML Model Performance tables (mAP, precision, recall, FNR, errors, pass rate), as dataframes or colored in-cell bars.
  • Major Performance Scores — mAP / precision / recall lines across versions with data-count bars.
  • Prediction Trend — minADE/minFDE @1/3/5 s across releases.
  • UseCase Metrics Trend and Pass Rate Trend — recall/FNR, overall + major/mid category pass rates; releases analyzed with perception_catalog_analyzer ≥ 0.2.0 add recall-by-distance-band lines.
  • Defect Evaluation — the major/mid/minor defect-category hierarchy per version as bars, treemap, icicle or sunburst, colored by pass rate, with a worst-first case table.
  • Release Details / Trend Details — per-release metric atlas heatmap (metrics × labels), minADE/minFDE label profiles, per-label timeline heatmaps.
  • Case Explorer / Grouped Raw Browser — drill from major → mid → minor → case; inspect the raw summary.json and group manifest per role.
  • Build Release Trend Group — the manual assembler: point at the three role summaries, provide the metadata YAML, and it creates the trend_release_… folder for you (each source must classify as its declared role).
Empty page?
