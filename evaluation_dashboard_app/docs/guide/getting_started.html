Getting Started

From evaluator job to first insight.

There are two ways to get evaluation results onto the dashboard: the manual path on the Download page (paste a job ID, download, evaluate) and the automated path on the Workflow page (schedule the evaluator job and let a background worker do everything). Both end at the same place: a run folder under data/ that you select on Overview.

Manual · Download page Automated · Workflow page Offline · Local desktop client
Path A — Manual

Download page: paste IDs, download, evaluate.

Use this when the evaluator job already finished and you just want its results locally.

01ConfigureSidebar: Project ID (e.g. x2_dev), Job ID or the full report URL (the ID is auto-extracted), optional Suite, and an Output Path dedicated to this test.
02DownloadTab “Download Results”. Pick Archives (ZIP) with a phase to extract, or Result JSON only. Or press the one-click Download + Eval + Parquet.
03EvaluateTab “Eval Results”: run eval_result, generate Summary.csv / Score.csv, and build scene_result.parquet.
04SelectOpen Overview, choose the new run as Baseline (A). Every other page now follows.
Download · results downloader

The Download page. Left: shared configuration (project, job, suites, output path, download type). Right: per-action tabs — Download Results, Download Scenarios, View Downloads, Eval Results.

Prerequisite for CSV generation

Generating Summary.csv / Score.csv needs a pilot-auto (ROS 2) environment with perception_eval importable — source path_to_pilot/install/setup.sh before starting Streamlit when running locally. In the Docker deployment the workers already have it.

Task queue vs inline

With USE_TASK_QUEUE=true (the production deployment) every heavy action becomes a background task with a live status list at the top of the page — you can close the tab. Without the queue, the same work runs inline in your browser session with a progress HUD.

Path B — Automated

Workflow page: schedule, wait, and land results automatically.

Use this when the evaluator job hasn’t run yet. Start new workflow schedules the job from a catalog, polls until it finishes, downloads, evaluates, and builds parquet — all as one background task. A release-mode variant schedules the standard Performance + DevOps catalogs and generates the release specsheet with trend metadata (see Specsheet & Trends).

Workflow · team control room

The Workflow page: everyone’s background tasks (with an opt-in “Only mine” filter and an optional pixel-office visualization), the Start new workflow dialog, PR test-branch preparation, and a browser of recent evaluator jobs with Details / Download / Retest per job.

  • Current Tasks — the whole team’s running/pending tasks by default; switch to “Only mine” when you have a Cloudflare identity. The 🕹️ pixel-office toggle renders active tasks as an animated office floor (hover a desk for status, click for details).
  • Run Evaluator Workflow — pick a catalog preset, branch/tag, and output folder; advanced options cover poll interval, max wait, download type, eval/parquet toggles. TLR catalogs are detected automatically and switch to result-JSON mode for the TLR Analysis page.
  • Recent evaluator jobs — search by branch, description, job ID, SHA or user; open Details, or press Run to queue Download + Eval + Parquet for an existing job.
  • Local Runs tab — every finished run on the server: filter by catalog/branch/user/date, inspect metadata, download a ZIP of artifacts, delete with typed confirmation, or tick several runs and press Compare to deep-link Overview.
Step 2 — Select On Overview

Pick Baseline A, add candidates, filter labels.

SINGLE MODE

One run under the microscope

Choose Baseline (A) in the sidebar. Overview shows Summary metrics (TP mean, XRMS/YRMS/XSTD/YSTD, per-label bars); detail pages show their single-run views.

COMPARE MODE

Baseline vs candidates

Switch the Mode radio to Compare, add Candidate (B) — and more with “➕ Add run” (C, D, E…). Every metric gains Δ-vs-baseline views, and pages like Detection Stats unlock recovered/lost object diffs.

Share any view as a link

Overview writes ?mode=…&run_a=…&run_b=… into the URL and shows the query in a “Shareable link” callout. Anyone opening that URL gets the same runs loaded — Data Management can compose these links too. Viewer pages add their own parameters (scene, frame, comparison layout), so even a specific 3D frame is linkable.

Compare delta looks empty?

Delta views join baseline and candidate on the Summary keys (id, plus perception_label when both sides have it). If the two runs share no keys, Overview warns “TP Summary delta views will be empty” and shows a key-overlap diagnostic table with sample one-sided keys.

Optional — Offline

The local desktop client.

evaldash-local is a self-contained app that pulls already-generated results from a running dashboard into a local workspace and serves the same bbox explorer/viewer against them — offline, without VPN, Streamlit or Docker. The default criteria download tier is about 18× smaller than the raw run. It can also fetch T4 point-cloud scenes for local 3D playback and start server-side workflows. Details in Deployment → Local desktop client. 

# from source
pip install -r client/requirements.txt
python3 -m client login --server https://your-dashboard.example
python3 -m client pull <run-name>          # default tier: criteria
python3 -m client open                       # opens the local home page

# or the packaged single file
./client/build_app.sh --server https://your-dashboard.example
dist/evaldash-local
