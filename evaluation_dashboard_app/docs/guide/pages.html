Overview

Overview.py · entry page

The control panel. Discovers run folders under the data root, selects Baseline (A) — plus Candidates (B…E) in Compare Mode — applies global perception/product label filters, loads everything into shared session state, publishes the shareable URL, and hosts both PDF exports.

Overview

Sections, top to bottom

  • Loaded data — one card per run (Baseline · A, Candidate · B…), with owner attribution when run metadata records who requested it.
  • Shareable link — the ?mode=…&run_a=… query to append to the server URL.
  • Summary metrics — TP mean (with per-candidate deltas), XRMS / YRMS / XSTD / YSTD tiles (mean + median · P95 · min · max), TP-mean-by-label bar charts, and a per-label metric breakdown expander. Needs Summary.csv.
  • Export Dashboard Report — generates the curated PDF from the current selection and filters (details).
  • Export Specsheet Report — the release spec-sheet PDF with optional trend context (details).

Compare mode

Loads every selected run with the same filters, computes the A-vs-first-candidate delta frame, and runs a Summary key overlap diagnostic: if a candidate shares zero join keys with the baseline you get a prominent warning plus an expander with row counts and sample one-sided keys.

Common blockers

“Data directory not found” / “No runs found” — the data root is missing or empty. “Summary.csv not found for this run” — a parquet-only run: Detection Stats and the viewers work, the metrics area and TP Summary / Criteria pages don’t.

TP Summary

pages/1_TP_Summary.py · needs Summary.csv

Kinematics and accuracy distributions over Summary.csv: how TP rate, X/Y position error (RMS/STD) and planar velocity distribute across the run — and, in compare mode, row-wise delta datasets per candidate plus a per-scenario ΔTP ranking.

Controls

  • Dataset (sidebar, compare only) — Baseline (A), any Candidate, or Delta (X − A); delta is the row-wise candidate−baseline after matching Summary keys. A Delta view is the default.
  • TP range slider and Clip velocity outliers (1st–99th percentile, on by default).

Views

  • At-a-glance — rows, TP mean/median/range; delta views add “Delta positive/negative %”.
  • Position RMS — xrms vs yrms scatter colored by TP; delta view shows candidate-vs-baseline scatters for X and Y side by side, colored by ΔTP.
  • Velocity — vx vs vy scatter (A and candidate side by side in delta view).
  • Metric distribution — histogram + violin for any Summary metric (or its _delta).
  • Per-scenario ΔTP — ranked diverging bars: largest absolute change, most improved, most degraded, custom name filter, or all.
“No delta rows”

Baseline and candidate share no common Summary keys (id + perception_label). Pick Baseline or Candidate in the sidebar instead, or load runs with overlapping rows.

Criteria Based Score

pages/2_Criteria_Based_Score.py · needs Score.csv

Reads the criteria blocks in Score.csv (one per criteria index, pass rate on the 0–100 scale) and turns the chosen block into distributions, grouped averages, per-scenario pass-rate comparisons — and an optional binary absolute pass/fail gate meant as the last checkpoint before release sign-off.

Controls

  • Criteria block (sidebar) — criteria0, criteria1, …; in compare mode the selector is limited to the minimum block count across runs.
  • Y-axis metric (default pass_rate) and Color / group by (GT_OBJ or Option).
  • Absolute pass/fail gates — perception-label filter (from Summary.csv), scenario filter (compare mode intersects the pools so counts are fair), minimum pass rate (default 95%), and an optional second numeric condition (metric + ≤/≥ + threshold).

Views

  • Final gate verdict — per run: verdict banner (“Gate cleared / not cleared”), scenario pass-rate progress bar, Pass/Fail donut, counts, failing-scenario table, and CSV export. With 2+ runs, Venn-style overlap and Sankey visuals with per-bucket scenario lists.
  • Compare workspace — tab Overlay (histograms per run, grouped averages, per-scenario pass rates on the inner join of all runs, per-scenario delta bars, optional baseline-vs-candidate scatter with parity line, CSV export) and tab Delta (delta distribution, mean Δ by group, largest 20 changes). A “Candidate for Δ vs baseline” selector appears with 3+ runs.
  • Single mode — distribution, ranked group means, pass-rate box plot, and a scenario leaderboard (top N, highest/lowest first).
Criteria · run without Score.csv

The page explains itself when the loaded run is parquet-only: Score.csv is required here.

Detection Stats

pages/3_Detection_Stats.py · needs parquet · the deepest page

The DuckDB-powered analysis surface for 3D object detection. One parquet per run is flattened into a cached view, then analyzed at increasing depth: global KPIs, per-class status distributions, distance-bin behavior, cross-run TP-rate comparison, and object-identity diffs that name exactly which GT objects flipped FN→TP or TP→FN. Frames 0–2 are always excluded.

Detection Stats · KPI card
Detection Stats · distance panels

Sidebar filters

  • Parquet file per run (when several exist), Exclude polygons (mirrors perception_catalog_analyzer: matched polygon TPs become FNs), Topic Name (equivalent topics are mapped across runs: objects ↔ tracking.objects ↔ detection.bevfusion.objects), Labels, Suites (prefix-matched across runs), Visibility, and Max Evaluation Range (50–150 m).

Sections, top to bottom

  • Summary KPIs — GT, TP, FP, FN, recall/TP rate, FP rate, precision, F1; per-run cards with deltas and an auto-written comparison paragraph in compare mode.
  • LLM analysis package — one click builds a ZIP of evidence tables plus a paste-ready prompt asking for an 11-section regression analysis report.
  • Status distribution per label — stacked bars, treemap, 100% stacked, or spider chart; CSV export.
  • Distance panels — TP rate, FP rate and object count by distance bin (line or bar), per-label breakdowns; compare mode adds label × distance change matrices (diverging heatmap of candidate − baseline). Single mode appends a bilingual narrative summary.
  • TP Rate comparison — spider chart (six fixed cutoffs ≤50/80/100/120/150 m + all), grouped bars, heatmap, or line profile per class.
  • Perception diff: GT TP/FN changes (compare only) — recovered (FN→TP) and lost (TP→FN) GT objects joined on t4dataset_id + frame_index + uuid, with one-sided-dataset guards, sunburst/treemap hierarchies (scenario → dataset → frame), comparison-lens treemaps, and drill-down tables whose rows carry “Open 3D” deep links into the T4 3D Viewer.
  • Perception diff: False Positives (compare only) — the FP mirror: baseline vs candidate FP counts per dataset/frame/label (FPs aren’t identity-matched), with the same guards, hierarchy, lens and exports.
  • FN by frame/object and Mean Error (single mode) — where the misses are, and mean |x/y/yaw error| on TP matches.
First load is slower on purpose

The page materializes a derived cache parquet per run (per polygon setting) under the run folder; subsequent loads reuse it until the source parquet changes.

Common blockers

“No parquet files found in run” — generate parquet from the Download page. “Topic 'X' could not be found in …” — pick __all__ or a topic that exists in every run. “All datasets … one side” — a run is missing whole datasets; disable the skip option to inspect them.

Prediction Evaluation

pages/12_Prediction_Evaluation.py · needs future.parquet / future.csv

Trajectory-prediction quality: best-of-K minADE / minFDE at 1, 3 and 5 s, aggregated with specsheet-aligned distance-bin averaging so the numbers match the release spec-sheet. Runs without future.parquet/future.csv don’t appear in the selector at all.

Prediction Evaluation

The cache-first workflow

Charts only render from a compact summary cache (<run>/.dashboard_cache/prediction_eval_cache/). Press Build A Summary (and Build B Summary in compare mode) once per run; the build shows staged progress (“Matching prediction tracks against GT…”) and invalidates automatically when the source file changes.

Views

  • At A Glance — six stat cards (minADE/minFDE @1/3/5 s, ≤60 m); compare mode shows A / B / Δ.
  • Label Performance — ADE/FDE matrix heatmap per label (delta heatmap centred on 0 in compare mode).
  • Distance Ladder — lines, metric heatmaps, circular rings (0–200 m in 20 m bins), label small-multiples; compare mode leads with delta heatmaps.
  • Polar Field — radius × bearing grids per label (B − A diverging in compare mode).
  • Metric Table — exact values, with _A/_B/_delta columns when comparing.

TLR Analysis

pages/9_TLR_Analysis.py · needs result.json directories

Traffic Light Recognition evaluation. Discovers TLR result directories (anything under the data root containing result.json — download them via the Download page’s Download Scenarios tab or a TLR-mode workflow), then analyzes criteria matrices, scenario summaries, vehicle-status × signal-type heatmaps, per-frame details, and embeds the TLR viewer. Selects its own data in the sidebar — no Overview run needed. Single directory, or A/B compare with shareable URLs (mode, path_a, path_b).

TLR Analysis

The six tabs

  • Criteria matrix — TP rate and frame counts per criteria; compare mode shows A/B/Δ tables, overlaid lines and signed delta bars.
  • Scenario summary — suite treemap, lowest-TP-rate scenarios, a performance-map scatter, vehicle-status mix, and a per-scenario timeline (markers by signal type and TP/FN, rolling and cumulative TP-rate lines).
  • Vehicle status vs TLR type — TP-rate heatmap of driving state × signal type; compare mode shows the Δ(B−A) heatmap (green = B better).
  • Critical & priority zones — the same matrices restricted to criteria 5–6 (critical) and 2–4 (priority).
  • Vehicle status details — one row per frame with filters/sorts and CSV/JSON export; compare mode joins A and B per frame and can show only frames where the recognized signal type differs.
  • TLR viewer — embeds the T4 server’s /viewer/tlr for a chosen dataset with per-frame evaluation data pushed into the iframe.
“No TLR result directories found”

The page looks for directories containing result.json under the data root — download scenarios first, and keep result JSONs next to them.

Download

pages/6_Download.py · data acquisition

Pulls artifacts from the Autoware Evaluator for a Project / Job / Suite, lands them under the data root, and optionally runs the local evaluation and parquet conversion. With the task queue on, every action is a background task with a live, auto-refreshing status list.

Download

The four tabs

  • 📥 Download Results — list available logs, download archives (with phase extraction and a large-file skip) or result JSON only, stop mid-way, open the output folder, or run the one-click Download + Eval + Parquet.
  • 🗺️ Download Scenarios — scenario.yaml + related resources (plus result JSONs), with name filtering, overwrite control and explicit scenario IDs. Required before TLR Analysis.
  • 📊 View Downloads — a browser of what landed under the current output path.
  • 🧮 Eval Results — run eval_result, generate Summary/Score CSVs, build parquet (each also available as a queued task); upload local CSVs/parquet into a run folder; optional browser notification when eval finishes.
Paths are sandboxed

Output and eval paths are entered relative to the server data root; anything escaping it is rejected. Paste a full report URL into the Job ID field — the ID is extracted automatically (same for Suite URLs).

Common blockers

“webautoauth not available” — the auth library isn’t installed / no web.auto profile. “Failed to enqueue task” — Redis/Postgres/worker missing while USE_TASK_QUEUE=true. Parquet buttons disabled — install perception_catalog_analyzer.

Workflow

pages/6_Workflow.py · team control room

Watch every background task, launch complete evaluator workflows (schedule → wait → download → eval → parquet), prepare pilot-auto PR test branches, reuse existing evaluator jobs, and manage the finished Local Runs on disk. Requires the task queue for anything that starts work.

Workflow · Run Tasks tab

Run Tasks tab

  • Current Tasks — team-wide by default with an “Only mine” opt-in (needs an identity via Cloudflare Access or AUTH_USER_HEADER); history range / rows / page controls; 3-second live refresh.
  • 🕹️ Pixel office view — optional: one desk + pixel worker per active task (walks in when pending, types while running, confetti on success, red monitor on failure). Hover for status, click for details; a “Manage active tasks” expander provides View/Stop since the canvas can’t run server actions.
  • Run Evaluator Workflow — the Start new workflow dialog: project, catalog (presets from catalogs.json or fetched live), branch/tag, output folder, phase, description; advanced options for download type, environment, poll interval, max wait, eval/parquet, polygons. Release data workflow mode schedules the fixed Performance + DevOps (+ optional Planning Test) catalogs, edits release metadata YAML inline with live validation, reuses existing job IDs, and shows a per-role execution plan. TLR catalogs auto-enable TLR mode.
  • Prepare Git Test Branch — builds a pilot-auto test branch from a sub-repo PR (universe / launcher + PR number + base branch) as a background git task.
  • Recent evaluator jobs — searchable job browser with Details (suites, failed cases, raw JSON) and Run (queue Download + Eval + Parquet with a suite picker).

Local Runs tab

  • Filterable table of every run on the server (search, catalog, branch, user, dates, artifact toggles) with per-run details, evaluator/GitHub links, artifact ZIP download, artifact retest, and typed-confirmation delete.
  • Compare bar — tick 2+ runs and press Compare to open Overview with them preloaded.

Parquet Debug

pages/8_Parquet_Debug.py · artifact inspector

A three-in-one inspector for the pipeline’s artifact formats. Choose the file type in the sidebar and pick a discovered file (or type a custom path).

  • Parquet — DuckDB-backed schema, row counts, PyArrow metadata, previews with substring search and up to four ANDed structured filters, per-column stats, distinct-value sampling, and an ad-hoc SQL box (SELECT * FROM read_parquet(?) LIMIT 10). Huge files are never fully loaded.
  • PKL — root object type, structure as table / expandable tree / text dump, previews of DataFrames found inside, JSON-safe sample values. Classes stored in the pickle must be importable.
  • result.json (TLR-style JSONL) — criteria condition table, success overview, success-over-line timeline, criteria-status-by-frame heatmap, per-line structure, and the trailing FinalScore.

Local Evaluator Debug

pages/14_Local_Evaluator_Debug.py · evaluator image console

A host-side console for evaluator images: queue a job that checks out a pilot-auto branch and builds it (CI-faithful sandbox or the older Docker multi-stage path), optionally run one WebAuto scenario with the built or an existing image, or commit a hand-modified container as a new image.

  • Submit tab — Build + test / Build only / Test existing image / Commit modified container; scenario command with auto-added defaults (runtime path, timeout, work dir, Agnocast mode…).
  • Container edit tab — start a container from an image, browse/load/edit files inside it, run shell commands, commit the result as a new image. Works without the queue if the app process has Docker access.
  • Logs tab — tail and download the full build/test log (task rows deep-link here).
  • Tasks tab — this page’s recent jobs with the standard task cards.
