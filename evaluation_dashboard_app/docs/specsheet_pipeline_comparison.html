Specsheet PDF With Trend Data: Dashboard App vs Direct awspec

Developer-oriented map of how this Streamlit dashboard generates a release specsheet PDF with trend data, compared with directly using the internal perception_catalog_analyzer / awspec library.

Executive Summary

In this workspace, awspec is not importable as a Python module. It is the Typer CLI name declared by perception_catalog_analyzer.cli. The app imports the library package directly as perception_catalog_analyzer.
APP

What the dashboard adds

Job scheduling/reuse, app-native downloads, role folders, trend metadata validation, DevOps summary synthesis, topic autodetection, compatibility shims, progress logging, and dashboard inventory/static links.

DIRECT awspec

What the library owns

SceneDataFrame loading, metric block generation, summary JSON production, trend plot rendering, template rendering, table-of-contents insertion, HTML output, and WeasyPrint PDF output.

BOTTOM LINE

Main difference

Direct awspec is a job-ID-centered export/PDF tool. The app is a release-workflow orchestrator that prepares dashboard-native artifacts, then calls selected analyzer functions through wrappers.

End-To-End Pipeline Difference

1. User starts release workflow Streamlit task submits run_release_specsheet_workflow with project, target, version, topic, labels, metadata.
→
2. App schedules or reuses jobs Performance + DevOps are required. Optional Planning Test can be added.
→
3. App builds local artifacts Downloads archives/results into data/release_spec_*/performance and devops.
→
4. App writes trend inputs Writes metadata.yaml, creates/reuses DevOps resources/summary.json, validates full summary.
5. App calls analyzer functions SceneDataFrame.from_dir, get_blocks, trend plot helpers, update_template, specsheet.
→
6. Analyzer computes sections Filters by topic, bins polar grid, computes abstract/detail HTML, writes block summary.
→
7. Trend context assembled App scans dashboard data root for metadata/summary pairs, then analyzer plot helpers write PNGs.
→
8. PDF rendered Template HTML + abstract/detail blocks become specsheet.html and specsheet.pdf.

Direct awspec all / awspec pdf Pipeline

1. User provides job IDs --full-job-id, --usecase-job-id, --devops-job-id, metadata paths, topic.
→
2. PathManager creates output shape output/export/{job_id} and output/pdf/{full}_{usecase}_{devops}/{topic}.
→
3. Library downloads/exports Performance jobs become current/future CSV or parquet. DevOps becomes devops.csv.
→
4. Library builds PDF build_performance_data, build_devops_data, build_trend_data, update_template, specsheet.

Important Behavioral Differences

AreaWhy developers should care
App may skip external downloads If local release folders already contain parquet/download artifacts, the app can bypass evaluator waiting/download. Direct awspec export is job-ID oriented.
App excludes some trend sources from scan discover_trend_metadata_files() skips paths containing _app_trend_history and any path under release_spec_*. This avoids double counting release workflow internals but means imported trend_release_* or standalone runs are the main history sources.
App validates full summary before rendering trend PDF If summary.json is absent or classifies as non-full, app trend generation fails early. Direct library trend building can silently skip metadata entries with no usable full summary.
DevOps trend shape is normalized by app The app accepts several nested pass-rate shapes, unwraps DevOps if present, and fills missing cases with zero-count entries so versions align in detail plots.
Analyzer API drift is hidden by app wrappers The app maps semantic kwargs onto the installed analyzer function signatures. Direct code that copies current analyzer calls may break across analyzer versions unless it uses similar wrappers.
Template dataset assets may be redirected The app patches analyzer template globals so dataset-summary files are copied into the specsheet context instead of relying on read-only package config paths.
PDF body role differs Direct awspec can combine full and usecase metric blocks. The current app release workflow calls generate_specsheet_pdf() on performance_path and uses evaluation_type="full" for the body; DevOps enters through trend/current pass-rate context.

Debugging Checklist

When using the dashboard app

  • Confirm release metadata contains tags: [trend], pilot_auto_version, data_count, and date.
  • Check performance/resources/summary.json or performance/specsheet/resources/summary.json classifies as full performance.
  • Check devops/resources/summary.json exists if DevOps trend/current pass-rate plots are expected.
  • Verify the requested topic exists in current.parquet/future.parquet; the app may log a detected-topic replacement.
  • Open performance/specsheet/trend_assets to verify PNGs were created before debugging template rendering.
  • Remember that release_spec_* paths are excluded from history scanning, so historical trend inputs should come from imported trend_release_* or standalone trend runs.

When using direct awspec

  • Make sure PathManager has full/usecase/devops job IDs if you expect trend folders and specsheet output paths.
  • Make sure metadata files are present under the library PDF tree; build_trend_data() scans pdf_path/**/metadata.yaml.
  • Confirm metadata parent structure matches analyzer assumptions because topic is inferred from path parents in library trend code.
  • Use --skip-download only when output/export/{job_id}/archive/*.pkl.z or exported files already exist.
  • If prediction trends are missing, check that future.csv or future.parquet exists and contains the selected topic.
  • If usecase metrics look different, remember direct library removes mAP and precision for usecase blocks.

Short Mental Model

Use direct awspec when you already have clean job IDs and want the analyzer's standard output/export plus output/pdf lifecycle. Use the dashboard app when you want a managed release workflow: scheduling/reusing evaluator jobs, app-native artifact storage, dashboard inventory, robust trend metadata handling, and compatibility across analyzer versions.
